# UIデザイン基準

作成: 2026-11-08（Codex。家族脳の本番実装に準拠）。追記の経緯は末尾の「変更履歴」。

## 目的と対象
家族脳、MAI2のWebアプリ、開発ダッシュボードに共通の見やすさと操作感を持たせる。スマートフォンで毎日使いやすく、広い画面の作業にも適したUIとする。配色はB（青）、配置はAを採用。各アプリの機能とAPIはこの基準だけを理由に変えない。

## デザイントークン
背景とカードを分け、青は主操作と選択状態に使う。赤は削除確認・エラー・期限切れ。意味は必ず文字でも示す。区切り線は装飾用、入力欄の境界には濃いborderを使う。配色は既定でOS設定に従い、設定からライト/ダークを明示選択できる。

| 用途 | ライト | ダーク |
|---|---|---|
| 背景 / 面 | #F7F8FA / #FFFFFF | #111827 / #1F2937 |
| 本文 / 補助文字 | #1A1A1A / #525252 | #F9FAFB / #CBD5E1 |
| 主色 / 主色上の文字 | #0031D8 / #FFFFFF | #66A6FF / #071A38 |
| 危険色 / 危険色上の文字 | #B3261E / #FFFFFF | #FFB4AB / #3B0B08 |
| 境界 / 区切り | #666666 / #D3D6DD | #94A3B8 / #4B5563 |

文字は端末のシステムフォント。iPhoneではヒラギノを用い、外部フォントを読み込まない。本文17px/行高1.7、補助14px（十分なコントラストを保つ）、見出し20px/1.5、画面タイトル24px、PCタイトル32px。太さ400・600・700。入力欄とプルダウンは家族脳では必ず17px以上、他アプリでも16px未満にしない。

余白4・8・12・16・24・32・48px。通常カード間24px、PCでは32px。角丸は操作8px・カード12px。面は1pxの区切り線と控えめな影で分け、ダークのカード影は省く。フォーカス枠は必要最低限とし、太い二重枠やタッチ端末でのタップ残留枠は出さない（入力欄は境界色の変化のみ、キーボード操作時のみ控えめな1.5px枠）。

## レイアウト
| 画面 | 切り替え幅 | 並べ方 |
|---|---|---|
| スマホ | 768px未満（375pxを検証基準） | 入力→一覧の1列。5種のタブを画面下に固定し、アイコンと文字を併記。本文下部にはナビ高とセーフエリア分の余白を確保 |
| タブレット | 768〜1199px | 上の横タブ、入力280px＋残り幅の一覧。外余白24px |
| パソコン | 1200px以上 | 左ナビ176px＋本文、入力320〜360px＋一覧。列間32px、外余白32px |
| 大きなパソコン | 1600px以上 | 左ナビ192px。予定の「家族の予定」「外部カレンダー」をさらに横2列 |

全体の最大幅1600px。長い本文は40rem、メモ編集面は56remを上限にする。広い画面でスマホの細い1列のまま中央表示しない。買い物など短い行は一覧の幅を活かすが、文章自体は40remを超えない。長い文字列はoverflow-wrap:anywhereで折り返す。CSS Gridの子はmin-width:0。768/1200/1600はこのアプリ群の独自基準。

## 部品の決まり
- 主ボタン: 青塗り、文字とアイコンを併記。通常高さ48px。副ボタン: 面色＋青枠。危ない操作: 赤枠と具体的な動詞。小さな補助ボタンも高さ44px以上。押せない状態は専用の背景と文字色を使い、透明度で薄めない。
- 入力・プルダウン: 見えるラベルを必ず付ける。高さ48px以上、文字17px、境界1px。プレースホルダーをラベルの代わりにしない。日付・時刻も横にはみ出さない。
- タブ: 選択状態は色、背景、線、aria-selectedで示す。アイコンだけにしない。スマホではリマインド列を他列の1.35倍にして、375px幅でラベルを1行に収める。文字拡大時は折り返しを許容する。PCでは左の縦ナビにする。既存のキーボード操作や選択状態を壊さない。
- 一覧: 主題600、日時と補足14px。カード余白16px・間12px。操作は行の右に配置。期限切れは赤い線と「期限切れ」の文字を併記。メモの開く行も44px以上でキーボード操作可能にする。
- 何もないとき: 情報アイコンと具体的な文章を枠内に表示。空白だけで済ませない。
- 読み込み中: 線画の回転と「読み込み中です」。prefers-reduced-motionでは回転を止める。
- エラー: 警告アイコン、赤枠、説明文。色だけで伝えない。外来のエラー文もtextContentで表示する。
- 知らせ: トーストはナビやセーフエリアの上に配置、最大幅640px。通知設定は専用パネルにまとめ、OSの許可を勝手に変更しない。
- 消すとき: confirm()を使わず既存の2回押しを維持。1回目で危険色と「もう一度押す」等の文に変え、3秒で元へ戻す。アイコンをラベルの書き換えで消さない。登録・完了・取り消しの既存条件は変えない。

## アイコン
24×24のviewBox、単色、線幅1.8、角はround、stroke=currentColor、fill=none。装飾SVGはaria-hidden=trueとfocusable=false、意味は隣の文字で伝える。絵文字・Unicodeの絵記号を操作アイコンにしない。

固定の場所はindex.htmlのインラインSVG。動的な一覧はdocument.createElementNSでsvg/pathを作り、固定パスだけを設定する。別案としてapp.cssの疑似要素とData URI SVGのmask-imageを使ってよい。新しい画像ファイルを増やさない。

使用してよい形: calendar（予定）、shopping（買い物）、tasks（タスク）、reminders（通知・リマインド）、notes（メモ）、plus（追加）、check（完了）、trash（削除）、back（戻る）、refresh（再読込）、info（空状態・情報）、warning（警告）、loader（読み込み）、share（ホーム追加手順）、settings（設定・独自の歯車）、close（閉じる・取り消し・独自の交差線）。MAI HQ で足した形（同じ線の規則）: send（送る・上向きの矢印）、copy（写す）、eye（詳細を見る）、agent（サブエージェントに任せた）、作業の記録の read（読んだ）・edit（編集）・command（実行）・search（検索）・reasoning（考えた）・tool（道具）・plan（計画）・file（変更したファイル）・stop（止めた）・chevron（開閉）。選択欄の開閉矢印はCSSの単色線で表現する（select は標準の矢印を消し、同じ線の矢印を Data URI の背景で描いて、ほかの開閉の矢印と形・位置をそろえる）。追加するときも同じ線の規則と出典管理に従う。

## アクセシビリティ
文字と実際の背景のコントラストは状態を問わず4.5:1以上。ライトだけでなくダーク、主/副/危険/無効/確認中/エラー/補助文を検証する。操作領域は高さ44px以上、通常48px。キーボードフォーカスを隠さない。ラベル、見出し階層、tabpanelの関連付けを維持する。文字拡大でも操作や長文が切れないよう折り返す。動きの低減と強制カラー表示に配慮する。

## iPhone・ホーム画面アプリ
viewportのmetaにwidth=device-width, initial-scale=1, viewport-fit=coverを指定。上・左右・下の余白にenv(safe-area-inset-*)を使う。下タブとトーストがホームインジケータや最後の行に重ならない余白を取る。入力17pxを維持してiPhoneの自動ズームを防ぐ。最小幅375px、縦横切り替えも確認する。

PWAはSafariとホーム画面起動の双方を実機確認する。通知は既存の仕組みを維持。sw.jsにオフラインキャッシュを足さず、古い画面を固定しない。今回manifestとホーム画面アイコンは変更していないため、既存アイコン/起動時の色は残る。

## 共通の守り
CSP default-src 'self'の中で作る。外部フォント、CDN、画像を使わない。style属性やHTML内のstyle/script直書きに頼らず、見た目はapp.css、動きはapp.jsに書く。AIや人が書いた文字はtextContentで表示し、innerHTMLを使わない。SVGのパスや属性へ外来文字を入れない。npmパッケージを追加しない。

鍵、メールアドレス、ネットワークの個別名、家族の実データを基準やサンプルに記載しない。確認は隔離した見本データで行う。画面や画面用APIを外部公開のAPIポートへ追加しない。

## 更新と検証
画面のトークンや部品を変えるときは、この基準も同じ作業で更新し、日付・作成者・変更内容を残す。共通ルールと各アプリ固有の動作を区別する。375/768/1280/1920pxのライトとダーク、長い文字、空状態、エラー、フォーカス、入力17px、操作44pxを確かめる。家族脳は隔離test.jsを実行し、JavaScript変更は、利用者が選択したメインモデルが差分・試験結果・画面の受入条件を確認する。本番反映やコミットは利用者の承認・依頼後に行う。

## 朝のまとめ・日付別履歴の表示

家族脳の「朝のまとめ」に適用する共通パターン。基本トークンは変更しない。

- スマホの上部は通常1行とし、アプリ名・「朝のまとめ」・歯車の設定を並べる。利用者名は設定の中に置く。ヘッダーは上部にstickyで固定し、上下左右のセーフエリアを確保する。操作は48px以上。文字拡大で収まらないときは切り詰めず折り返しを許容する。
- 本文の外に日付・生成の種類・配信状態を表示する。本文はLINEに送った原文をtextContentとwhite-space: pre-wrapでそのまま表示し、冒頭・絵文字・【見出し】・改行・空行・空白を省略/加工しない。配信済みと生成済み/送信未確認を、文字と線画アイコンで区別する。色だけに頼らない。
- スマホは本文、その下にバックナンバー。768px以上は本文と右の履歴一覧を横に並べる。本文は40rem上限、履歴列はタブレット240px以上、PC280px以上とする。
- 一覧の日付はクリックとEnter/Spaceで選べる。選択中は背景・線・aria-currentで示す。連続して選んだときに、遅れて届いた古い応答で新しい選択を上書きしない。
- 当日分が無いときと履歴がゼロのときを別の文章で案内する。閲覧だけでAI生成や対外通知を発生させない。
- 保存された文章はtextContentで原文どおり出す。配信用の冒頭や行頭の絵文字も省略・置換せず、保存本文・配信本文・画面本文を一致させる。
- バックナンバー一覧は最新400件まで表示し、古い分も17px・高さ48pxの日付入力「日付から開く」で直接開ける。送信未確認は配信失敗確定と区別する。
- 取消には24×24の単色線画の×アイコンを使い、ゴミ箱アイコンは削除操作に限る。
- ダークの :root には color-scheme: dark を明記し、日付入力などOS標準部品も配色を合わせる。

### 原文を保つ表示
通知履歴・会話履歴は、見た目を整えるために本文を再編集しない。文字列は保存・取得・表示で一致させる。装飾や配信状態は本文の外に置く。自動折り返しと本文幅40remの上限で読みやすくする。過去の送信文を利用者提供から取り込む場合、分からない生成/送信時刻を作らない。

### 省スペースのヘッダーと設定
- 日常の導線はアプリ名と主要画面への操作に絞り、通知などの個別設定は設定パネル内の見出しごとにまとめる。将来の項目は必要になってから追加し、空のメニューを作らない。
- スマホのヘッダーは通常1行・上部固定（position: sticky; top: 0）。背景は既存の不透明な背景トークン、区切り線は既存のdivider。上・左右にenv(safe-area-inset-*)を適用する。コンパクトなスマホヘッダーのタイトルは20pxを使用できる。
- 主要操作「朝のまとめ」は文字も表示。設定はスマホで歯車だけでもよいが、aria-labelとtitleに「設定」を付け、24x24のSVGは装飾扱いにする。タブレット/PCは歯車と設定ラベルを併記する。
- 設定はモーダルではなく本文内の開閉パネル。aria-expanded/aria-controls/hiddenを同期し、設定h2の下へ利用者名、表示h3、通知h3を置く。閉じる操作とEscapeを用意する。明示的に開いたら見出しへ、閉じたら設定ボタンへフォーカスを移す。自動案内ではフォーカスを奪わない。
- スクロール下部から開いてもパネル冒頭を見せ、固定ヘッダーが見出しや入力欄のフォーカスを覆わないようscroll-padding/scroll-marginを用意する。文字拡大では一行への固執による切り詰めを避ける。
- 通知設定を開くだけでOSの許可ダイアログを出さない。既存の通知オン/オフ/テスト操作と安全条件を維持する。PCの広さを活かすレイアウト、下ナビ、入力17pxは維持する。

- 固定ヘッダーの操作部分は48px以上、上下8pxとセーフエリアの余白を取り、標準375px見本では高さ約65px。設定の「閉じる」も48px以上とする。
- フォーカス用のスクロール余白は、実際のヘッダー高＋16pxに連動する。家族脳ではResizeObserverで測り、同一オリジンの既存app.cssの:rootルールにある--header-heightをCSSOMで更新する。style属性や新しいstyle要素は作らない。実測できない場合の初期値は160px＋上セーフエリア。全幅でヘッダーを上部に固定する。下記「アプリ共通のヘッダー」の規定を適用する。

### 必須・任意のフォーム表示
- フィールドの見えるラベルは短く保ち、「なくてもよい」を付けない。必須項目にはASCIIの * を添え、フォームの見出し横へ「* 必須」の凡例を置く。ネイティブのrequiredと、編集画面の非空チェックの意味を維持し、印だけに頼らず読み上げにも必須状態を伝える。
- 任意欄は、空・非フォーカスの間だけ入力枠内に既存muted色で「任意」を表示する。入力値が入ると消し、空へ戻すと再表示する。フォーカス中はネイティブの編集表示を優先する。ラベルは常時残し、読み上げにはaria-describedbyで任意の説明を関連付ける。
- date/timeにはplaceholder属性を使わない（標準では非対応）。元のtypeと標準ピッカーを維持し、補助表示を固定のspanで重ねる。補助はaria-hidden・pointer-events:noneとし、空・非フォーカスの入力文字を透明にし、surface背景で空欄の標準表示と重ならないようにする。補助文字は明示のmuted色とし折り返さない。右端40pxは空け、カレンダー/時計アイコンを覆わない。入力値そのものや送信形式を変えない。
- 任意の担当プルダウンは空値の表示名を「任意」とし、空選択時だけmuted色。選択した人名や値は変えない。input/change/blur、フォームリセット・初期化・候補再生成でも表示を同期する。入力途中のbadInputは空欄扱いせず、入力内容を覆わない。
- 入力文字17px、操作48px、コントラスト4.5:1以上は維持する。凡例は既存の補足文字トークン14pxを使う。ネイティブのrequired条件やAPIの検証を表示変更に合わせて弱めない。
- 参考: https://html.spec.whatwg.org/dev/input.html （date/timeでplaceholderを用いないための根拠）。

### 設定内の配色選択
- 設定に「表示」セクションを設け、「配色」の選択肢を「端末に合わせる・ライト・ダーク」とする。入力文字17px・操作48pxの標準プルダウンを使う。
- 既定は端末の配色に追随。ライト/ダークを選んだらOSより優先し、背景・文字・線・フォーカス・影・標準日付ピッカーまで同じテーマへ切り替える。既存の明暗トークンを共用し、新色は増やさない。
- 選択はこのブラウザのlocalStorageへ固定の3値だけ保存する。他端末・API・家族データへは送らない。保存不可でもその場では切り替わり、不正な保存値は端末追随へ戻す。
- 外部app.jsから非同期API取得より先に復帰。CSPに従いinline scriptやstyle属性は作らない。theme-colorは選択中の配色と矛盾させない。
- 設定パネルを開く操作だけで配色や通知権限を勝手に変えない。

- 保存失敗時は「保存できないため、今回はこの画面だけに適用します。」と案内し、次に保存が成功したら通常の説明へ戻す。

## 可視化・ダッシュボード部品：開発の木（星団表示）

開発ダッシュボードの3D可視化（開発の木、Three.js）に適用する共通パターン。基本トークン（配色B・配置A）は変更しない。件数が増えると木というより星団に見えるため、本節ではこの見た目を「星団表示」と呼ぶ。

### 全体形
- 中心はCore（利用者）。第1階層はPJで、PJごとに方位セクターを固定割り当てする。他PJの増減で既存PJの居場所を動かさない（空間記憶を守る）。
- 配置は中心から球状に放射する。半径が表すのは進行の段数（世代）だけとし、枝の長さの微差・角度・密度に時間・工数・進捗率の意味を持たせない。凡例にその旨を明記する。
- 完全な球形の再現より、PJの識別と枝先（現在地と次のマイルストーン）の読みやすさを優先する。装飾のための色・形は足さず、色と形はすべて意味に割り当てる。

### ノードの色と形
- 仕事の状態は色・形・記号の組み合わせで表し、色だけに頼らない。これから＝白抜きの丸、実装中＝紫の半分塗り、完了＝緑（ティール）のチェック、運用中＝二重丸。色値は開発ダッシュボードの実装値を正とし、本節では新しい状態色を増やさない。状態は1ノードに1つだけ。
- 確認待ちは状態ではなく別軸の印とし、茶色の札で重ねて示す。ノード自身の印と、配下の集約印（「配下に確認待ちN件」）は分けて数え、表示する。件数タイルが数えるのは仕事（葉）だけとする。
- 知識（ADR、つまずきと解決）はひし形とし、仕事の丸と形で区別する。マイルストーンは大きめの節点＋輪で強調する。畳んだ過去は点も残さず隠し、線だけを残す（下の「省略しても経路を切らない」）。
- 線は最初は2種だけとする。進行＝実線、PJをまたぐ依存＝破線アーク。知識との関連は3Dに線を引かず、詳細でのみ示す。

### ラベル
- 3D上の文字はHTMLの札で重ね、テクスチャに焼き込まない。常時表示は「Core／PJ／進行中／次のマイルストーン／確認待ち／選択中」に限る。他はホバー・タップ・一覧で読む。
- 件数が増えたらラベルは優先順位つきで間引く（目安：500件級で最大14件、スマホ幅では6件）。間引かれた項目へは検索と一覧で必ず辿れることを条件とする。

### 規模への対応
- 表示は規模で切り替える。小規模（数十件級）は枝を面として描けるが、大規模（500件級）は枝を細い線にし、ノードを小さくし、一覧はPJごとに「先頭＋他N件」に畳む。
- 状態タイル・構成比・確認待ち件数などの集計は、表示中のデータ量で再計算して示す。集計と確認待ち巡回は、大規模になるほど価値が上がる部品として残す。

### 省略と履歴
- 通常表示は「直近の完了・進行中・次のマイルストーン」を中心とし、過去はトグルで開く。省略は削除ではなく畳みであり、畳んだ境界には要約（過去N件など）を残す。
- 未解決のものは畳まない。確認待ち・保留・撤回した判断・分岐の合流点は、履歴を畳んだ状態でも辿れるようにする。
- 展開・収納の前後で、選択中のノードと所属PJの画面位置が大きく動かないようにする。

### 進捗と鮮度（レンズ）
- 状態表示を正本とし、その上に切り替え式のレンズを重ねる。レンズは同時に何枚も重ねない。
- 進捗レンズ：枝ごとに、Core側から完了した所までを完了色で染め、実り具合を長さで読ませる。PJ単位の完了率を文字でも併記する。
- 鮮度・放置レンズ：最終更新からの経過で鮮やかさを変える。目安は、最近更新＝鮮やか、14日以上無更新＝色褪せ、実装中なのに長く無更新＝要注意として輪と文字で示す。放置は「放置中の枝」一覧（放置日数順）でも示し、色だけに頼らない。
- 進捗も鮮度も、レンズを外せば元の状態表示にそのまま戻る。

### 操作
- 回転・拡縮・パンを備える。通常モードでは縦スクロールとページのピンチを優先し、木のピンチ拡大とパンは全画面モードを主とする（ページ操作との競合を避けるため）。PCでは右ドラッグ／Shift+ドラッグのパンと、キーボード矢印（キャンバスにフォーカス時）を用意する。
- ノードの長押し（スマホ）／右クリック（PC）でメニューを出す。項目は「このノードを中心にする」「この枝だけ表示」「内容の詳細へジャンプ」「中心をCoreに戻す」。中心化はレイアウトを作り直さず、カメラと回転中心を寄せる方式とし、中心がどこか（「中心：○○」）を文字で示す。長押しが成立したらドラッグ回転は始めない。
- メニューの各操作は、詳細パネル内のボタンなど、キーボードでも到達できる代替を用意する。詳細へジャンプしたときは詳細の見出しへフォーカスを移す。
- 確認待ち巡回（前へ／次へ、端では無効）は規模によらず維持する。

### 検証
- 375／768／1280／1920pxのライトとダーク、長い名前、ラベルの間引き境界、500件級の描画、履歴トグルの前後での位置安定、色覚近似とグレー表示、動きの低減（prefers-reduced-motion）を確認する。
- 実iPhone Safariの長押しメニュー・ピンチ・パンの実機確認が済むまでは、その旨を記録に残し、確認済みと混同しない。

### 進行線・系譜・説明の置き方

上記の星団表示に次を加える。
- 進行の枝は直線基調とし、曲線は依存の破線アークだけに使う。順番の手がかりとして、世代ごとの同心球殻（段数の目盛り）、枝のグラデーション（親側を濃くし、進む向きに色を移す）、選択中の主経路の太線と矢印を用いる。動きの低減時は流れる点などのアニメーションを止め、矢印のみで向きを示す。
- ノード選択時は、そのノードに連なる系譜（祖先チェーン・子孫・関係する知識／依存）だけを強調し、無関係な要素は消さずに淡くする。「枝だけ表示」（消す方式）とは別部品として使い分ける。詳細には系譜の件数要約（祖先・子孫・知識・依存）を出す。
- 説明的な長文（設計の解説、規模を変えたときの所見、反例など）は画面本文に常時並べず、インフォボタンから開くモーダルに置く。凡例などの要点は表示面の近くに残してよい。モーダルは閉じる操作・Escape・フォーカスの往復・背景スクロールの固定を備える。

## ダッシュボード・可視化画面の構成

件数の帯と主役の表示（図・一覧・グラフ）を持つ画面に共通で使う（開発ダッシュボード・家族脳・MAI2）。見た目の格好よさと使いやすさを両立させ、アプリ間の統一感を保つための決まり。基本トークン（配色B・配置A）は変更せず、新しい色・角丸・余白は足さない。

### 最初の画面に置くもの
- 並びは使う頻度の順にする。①見出しとヘルプ、②状況の帯、③毎回使う操作、④主役の表示、⑤詳細。凡例・PJ別の内訳・全件の一覧・更新情報は主役の下に置く。
- 主役の表示は、スマホ（375×812）で画面を開いたときに上端が見えていること。目安は開始位置が画面の高さの6割以内。件数タイル・カード・設定を主役の上に積み上げない。
- 状況の帯は1〜2段に詰める。4状態は4列、別軸の件数（確認待ち・放置ぎみ）は2列、構成比は細い帯（8px）。数字を大きく、名前は短く1行にし、補足はタブレット以上で出す。1200px以上では全てを1段に並べる。タイルは絞り込みのボタンを兼ね、押した状態はaria-pressedと線で示す。
- 常設する操作は毎回使うものだけ（開発の木では検索・履歴・知識）。配色・レンズ・データ量・まれな絞り込み・全解除は「設定」ボタンで開く面へ畳む。ボタンはaria-expandedとaria-controls、面はhiddenで同期し、開閉の向きを線の矢印で示す。畳んだ中の操作も44px以上・入力17pxを守る。
- 768px未満では常設の操作ボタンを1行に収める。収まらない文言は短くし、文字を14px未満にしない。

### 主役の表示（作業面）
- 高さはスマホで画面の約64%（最小360px）、900px以上で約74%（最小480px）。900px以上は主役と詳細を横に並べて同じ高さに揃え、詳細だけを内側でスクロールする。ページ全体が詳細の長さに引きずられないようにする。
- 「全体に戻る」と初期表示は、固定の距離や倍率ではなく、表示中の全項目が収まる距離を計算して決める。向きは重なりが最小になるものを固定の候補から選び、同じデータなら同じ向きにする。縦長の画面でも端の項目を切らない。
- 作業面の大きさが変わったら（設定の開閉・全画面・列幅の変化）、描画の大きさと縦横比を合わせ直す。
- 作業面に重ねる札と操作ボタンは、面色を少し透かして背後が分かるようにしてよい。文字と背景のコントラスト4.5:1、操作44pxは守り、強制カラー表示では不透明に戻す。札は角を丸め、1行で省略する。
- 目盛りや補助線は、意味のある最小限の線にする。網目のような細かい装飾線で主役を覆わない（開発の木の世代の目盛りは、直交する3本の大円の線）。
- CSS Gridの列はminmax(0,1fr)、子はmin-width:0。整形済みテキスト（pre）や長い別名が列を押し広げて横スクロールを作らないようにする。

### 省略しても経路を切らない
- 履歴や絞り込みで項目を省略するとき、隠すのは項目そのもの（ノード・札・一覧の行・当たり判定）だけにする。表示中の項目へ至る線は、元の折れ線のまま残す。
- 両端のどちらかが隠れた線を消さない（残った項目が宙に浮く）。隠した区間を直結する線を新しく描かない（記録にない進行になる）。原データは書き換えない。
- 選択中の主経路・矢印・流れる点も、隠れた項目の位置を通って連続させる。経路の末尾が隠れた項目で終わる場合だけ、そこを切り詰める。
- 依存など別種の線は、進行の線と混同しないよう従来どおり両端が見えるときだけ出す。

### データの出所を画面に出す
- 見本・隔離データ・開発記録など、本番の実データでないものを表示しているときは、見出しの横の札に出所を文字で示す（例：「隔離デモ」「隔離デモ＋開発記録」）。読めなかったときは短い状態文を出し、内部のパスや例外文は出さない。

### 検証に加えること
- 画面を変える作業は、着手の最初に実ブラウザで375幅と1280幅の明暗を撮り、主役の開始位置・全体が収まるか・横はみ出し（ページの幅が画面幅を超えていないか）を数値と画像で確かめる。要素の有無を確かめる試験だけで、位置と大きさを確認済みにしない。
- 仕上げの確認は375／768／1280／1920のライトとダーク。設定の開閉、全画面の出入り、省略の切替前後で経路が連続していることを含める。実機で確かめていない項目は未検証として記録する。

### 検索・絞り込みの件数
- 件数は条件に直接一致する項目を数える。関係を見せるため残す祖先を一致件数へ加えない。履歴設定で非表示の項目は除く。
- 仕事・節目・知識・PJが混在する検索では、仕事だけを数えて0件と表示しない。「一致 1 件（知識 1）」のように合計と存在する種類の内訳を短く示す。
- 3Dだけの表示設定と一覧の検索条件を混同しない。画面修正時は知識のみ・節目のみ・0件のケースを確認する。

### アプリ共通のヘッダー

- タイトルの先頭にアプリを識別できるアイコンを1つ置く。ホーム画面用のアイコンがあるアプリでは、ヘッダーにも同じ画像ファイルを元の配色で表示し、アプリ名を文字で併記する。家族脳は既存の apple-touch-icon.png（緑地に白い家と赤いハート）を24pxで表示する。隣のアプリ名と重複する画像は alt="" とする。操作ボタンには従来どおり単色の線画を使う。
- スマホ・タブレット・PCとも、ページをスクロールしてもアプリ名と主要操作を上部に残す。通常幅では1行。文字拡大時は折り返せること。背景は不透明とし、上・左右のセーフエリアを確保する。
- 固定ヘッダーの実際の高さを、本文のフォーカス移動と固定サイドナビの上端に反映する。家族脳では scroll-padding と左ナビの top にヘッダー高＋16pxを使う。
- 画面レビューでは375・768・1280・1920pxの明暗両方で実際に本文をスクロールする。タイトルと操作の固定、左右のはみ出し、設定ボタンの押しやすさ、見出し・入力欄・左ナビがヘッダーに隠れないことを確認する。Safariとホーム画面起動での確認結果は、PCブラウザでの確認と分けて記録する。
- PCで左サイドバーを使う画面では、ヘッダーとナビを全タブ共通にし、設定を開いても同じ位置に保つ。縦スクロールバーの有無でタイトルや右端の操作が動かないよう余白を確保する。レビューでは本文の長いタブ・短いタブ・設定を切り替えて位置を比較する。

### PCの左ナビの見た目

- 1200px以上の左ナビは、面色の箱や縦の区切り線で囲まず、背景（--bg）に直接置く。中身より長い箱を画面の下まで伸ばさない。
- 項目は高さ48px、文字17px・太さ600、アイコン24pxと文字の間12px、項目の間4px、角丸8px。左右の余白は14px。
- 選択中は、薄い主色の面（--brand-soft）＋主色の文字＋太さ700＋aria-selectedで示す。面と線を重ねない（左の色線は付けない）。スマホの下タブとタブレットの横タブは、従来どおり線も併用する。
- ポインタを乗せた項目は、面色（--surface）と本文色にする。選択中の主色と紛れさせない。
- フォーカスの輪郭（3px）がナビの端で切れないよう、ナビの内側に3pxの余白を取る。強制カラー表示では選択中に枠線を出す（既存の決まり）。

### 説明文の最小化とインフォモーダル

- 通常の画面には操作ラベル・入力値・現在の状態・エラーや危険操作の確認など判断に必須の文字だけを残し、補足的な説明文を常設しない。
- 補足や手順の説明が必要な箇所は、見出しや操作の横にインフォボタン（既存の単色線画 `info` 24×24 SVG、操作領域 44px×44px 以上、`aria-label` で何の説明かを明示）を置き、押したときだけモーダルで表示する。
- モーダルは既存の面色・文字色・区切り線・角丸 12px に従い、ライト／ダークの両配色に対応させる。`×` ボタン・「閉じる」ボタン・Esc キー・背景操作のいずれでも閉じられ、閉じたあとは元のインフォボタンへフォーカスを戻す。
- 選択できない状態・空状態・承認確認の差分・エラー内容など、誤操作防止や状況把握に直結する短い表示は常設のまま省略しない。

## 道具の画面（MAI HQ など、利用者ひとりが毎日使う操作画面）

家族みんなが読む画面（家族脳）とは分けて、利用者ひとりが AI や作業を操作する道具の画面は、T3 Code のような密度に寄せる（2026-11-26 利用者がスマホで T3 と並べて判断）。色・コントラスト・押せる範囲・textContent・CSP などの共通の決まりはそのまま守る。

- **文字**: 本文 15px（行の高さ 1.6）、補助 13px、見出し 17px、画面タイトル 20px。入力欄とプルダウンは 16px（iPhone の自動ズームを防ぐ下限）。家族脳の本文 17px・入力 17px は変えない。
- **枠を重ねない**: 外枠の中に会話の枠、その中に吹き出し、のように枠を重ねない。会話は背景の上に直接並べ、PC では本文の列を 56rem までにして中央に置く。自分の発言は右寄せの吹き出し、AI の返事は吹き出しにせず幅いっぱい。送り手の名前の行は見た目から外し、読み上げ用に残す。
- **アイコンだけのボタン**: 主な操作（新規・設定・送る・詳細を見る・閉じる・写す・探す・凡例）はアイコンだけにしてよい。枠なし・背景なし、ホバーで薄い背景、押せる範囲 44px、元の名前は aria-label と title に残す。新規と送るは主色で塗った丸（44px）。**文字を残すもの**: 許す・断る・止める・中断・解除など取り返しのつかない操作、「もう一度押すと…」に変わる2回押しのボタン、設定の中の送信ボタン。
- **一覧（左のナビ）**: 行ごとの枠と大きな丸の印を使わない。枠なしの2段（1段目は小さい補助色でPC・AI・フォルダ、2段目は太字の題を1行で省略）、右端に小さな状態の印と最後に動いてからの時間（今・5分・3時間・2日）。選んでいる行は主色の薄い背景。一覧の見出しや「前のセッションを探す」などの説明の文字は置かず、探す・凡例のアイコンを一覧の下の帯に固定し、一覧だけを中でスクロールさせる。スマホの引き出しは、左へ払うと閉じ、左端から右へ払うと開く。引き出しの中は文字を選べないようにする。
- **作業の記録**: 枠なしの1行の折りたたみ（「◯秒作業しました」）。開くと種類のアイコンつきの行が並び、サブエージェントに任せた分は「任せた: 説明（種類）」の行の下に一段下げて入れる（2段まで）。
- **承認**: 会話の流れの最後に詳しいカード、入力欄の上に1行の帯（カードが見えている間は隠す）。「見送って別の指示」は畳んでおき、押したら入力欄を出す。
- **入力欄**: 入力・添付・送るを1つの枠にまとめ、高さは中身に合わせて伸ばす（約8行まで）。Ctrl+Enter（Mac は ⌘+Enter）で送り、Enter だけは改行。日本語の変換中は送らない。PC だけ入力欄の案内に「（Ctrl+Enter で送信）」を添える。
- **メニューの小窓**: 枠つきの大きな箱を重ねない。上に「小さい見出し＋選ぶ欄」の行、下に枠なしの操作の行。危ない操作は区切り線の下に赤い文字で置く。
- **スクロールバー**: 細く控えめに（標準の scrollbar-width: thin と scrollbar-color。未対応のブラウザだけ ::-webkit-scrollbar で補う）。つまみは背景に対して 3:1 以上。ページ自体がスクロールしない作りでは scrollbar-gutter: stable を付けない（右端に帯が残る）。
- **時刻の表示**: 移行で仮の値が入った古い記録は、ありえない時刻（2020年より前など）を出さずに空欄にする。
- **確認**: 見本の画面（作り物のデータだけを返す、127.0.0.1 だけで待ち受けるサーバー）で 375 / 768 / 1280 / 1920px とライト・ダークを撮って確かめる。375px は窓を狭くできない headless ブラウザでは iframe で包んで撮る。
