# ADR-0007: 教科を追加するときの保存モデル

- Status: Accepted
- Date: 2026-08-26

## Context

2教科目として単位を追加する（[units-plan.md](../units-plan.md)）。既存の保存層は漢字だけを想定した形になっている。

- `validateDailySession` は `mode` が `reading` / `writing` 以外の当日セッションを拒否する。
- 当日セッションのIDは `${localDate}:${mode}:${batchNumber}`、索引は `[localDate, mode]` で、どちらにも教科が入っていない。
- `DailySessionItem` の `impacts` は漢字をキーにした辞書、`unknownKanji` は漢字の配列である。
- `KanjiState` は1文字の漢字をキーとし、`reading` / `writing` の集計を持つ。
- 一方で `StudyAttempt.subject` とマニフェストの `packs[]` は複数教科を想定した形になっている。ただし `validateManifest` は `kanji` 以外のパックを例外にする。

取りうる両極は、漢字用のモデルを教科非依存へ一般化するか、教科ごとに保存経路を丸ごと複製するかである。前者は動いている漢字の実装すべてに触れ、既存のIndexedDBレコードの書き換えを伴う。後者は当日セッションの共有部分まで二重に持つことになる。

## Decision

形が本当に共通なところだけ共有し、教科ごとに違うところは分ける。

- **回答履歴（`attempts`）は1つのまま共有する。** 既に `subject` を持ち、ADR-0002のとおり正本である。教科を増やしてもストアを分けない。
- **当日セッション（`sessions`）は共有し、`subject` を追加する。** `subject` が無い既存レコードは読み出し時に `kanji` として扱う。移行のために既存レコードを走査して書き換えることはしない（進捗更新などで元から書き換わるレコードが、その際に `subject` を持つようになるのは構わない）。セッションIDとホーム画面の当日集計を `subject` 込みにする。
- **索引は `[localDate, mode]` のまま変えず、教科の絞り込みはメモリ上で行う。** `subject` を索引キーに加えると、そのキーを持たない既存レコードが索引から丸ごと外れて読み出せなくなるため。単一利用者の1日分の件数では走査量は問題にならない。
- **セッション項目の結果部分は `subject` による判別付きの形にする。** 漢字の `impacts` / `unknownKanji` を他教科へ流用しない。
- **苦手度の集計ストアは教科ごとに分ける。** 漢字は `漢字 × 読み/書き`、単位は `系統 × 出題形式` で、キー空間が対応しない。無理に1つのストアへ入れない。
- **回答保存関数は教科ごとに用意する。** 各関数が、回答履歴・当日セッションの進捗・その教科の集計・1ポイント加算（ADR-0006）を同一トランザクションで確定する。
- **`validateManifest` は、`kanji` 以外のパックを公開する前に既知の教科一覧へ広げる。**
- 教科横断の「今日の復習」と出題比率は今回決めない。当面は教科ごとに独立した入口とする。

## Consequences

- 漢字の経路に手を入れずに単位を追加できる。既存の当日セッションレコードを書き換える移行が要らない。
- 新ストア追加のため `STUDY_DB_VERSION` を4へ上げる。AGENTS.mdの規則どおり、既存の回答履歴・漢字別集計・履修設定・ポイント・ペット状態を保持する移行テストを先に作る。
- 回答保存トランザクションの形が教科ごとに重複する。何が原子的に確定されるかという不変条件のほうが重要なため、この重複は受け入れる。3・4教科目で同じ形が繰り返されたら、そこで共通化する。
- 教科の追加は次のチェックリストになる。マニフェスト検証、パック読み込み、当日セッションの `subject`、集計ストア、ポイント加算を含む保存経路、ホームの入口、がんばり記録への反映。
- ポイント加算が各教科の保存経路の中にあるため、追加時に書き忘れるとADR-0006の「どの問題でも回答すれば1ポイント」が黙って崩れる。教科ごとに機械ゲートで確認する。
- `sessions` へ `subject` を持たせたことが、後で教科横断の「今日の復習」を設計するときの接続点になる。
