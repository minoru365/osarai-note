# ADR-0014: 学習データのバックアップ・復元・初期化

- Status: Accepted
- Date: 2026-11-26

## Context

[ADR-0001](./0001-local-first-pwa.md) は学習データを端末内のIndexedDBだけに置き、端末移行やブラウザデータ消去への備えとして保護者操作のJSONバックアップ・復元を用意すると決めていた。[study-support-plan.md](../study-support-plan.md) 9章は、復元を全データ検証後に単一トランザクションで置き換え、途中失敗時は既存データを維持すること、削除・初期化・復元は対象を明示して保護者が再確認した後だけ実行することを求めている。[ADR-0006](./0006-motivation-points-and-pet.md)・[ADR-0009](./0009-shared-grade-selection.md)・[ADR-0012](./0012-motivation-fairness-and-fantasy-progression.md) は、ポイント・ペット・学年をバックアップ対象に含めると決めている。スマートフォンでも使うようになり（[ADR-0013](./0013-phone-layout-and-readability.md)）、データ消失の機会が増えた。

## Decision

- 保護者設定の画面上部から入る専用画面「データの保存と復元」に、保存・復元・初期化を置く。
- **保存**：IndexedDBの全7ストア（`attempts`・`kanjiStates`・`customQuestions`・`sessions`・`settings`・`motivation`・`unitStates`）を1つの読み取りトランザクションで読み、**生の記録をそのまま**JSONに書き出す。画面用の補正（学年の絞り込み、ペット状態の継続処理、初期値の補完）は通さない。ファイル名は端末の日付で `osarai-note-backup-YYYY-MM-DD.json`。個人情報は元々保存していない。
- **形式**：`{ format: "osarai-note-backup", formatVersion: 1, dbVersion, exportedAt, stores: { 7ストア: 記録の配列 } }`。
- **検査**：復元の前に全件を検査する。形式の印と版、DB版、書き出し日時、7ストアがちょうどそろっていること、各記録がオブジェクトでキーを持ち重複しないこと、ペット状態（読み込み時の継続処理後）の順序と範囲を確かめる。回答保存時の厳しい検査は使わない。古い版のアプリが書いた記録（科目のない回答やセッション、v1の漢字記録、2匹完了で次の仲間がいないv3のペット状態）はその検査を通っていないため、書き出したものが戻せなくなる。20MBを超えるファイルは読まない。
- **DB版**：今のDB版（4）と同じものだけを受け付ける。古い版のバックアップはまだ存在しないため、受け付けると試せない約束になる。DB版を5へ上げるときは、版4のバックアップを移行する経路と試験を同時に作る。
- **復元**：中身（保存日時、回答の記録数、漢字の記録数、ポイント、育てた仲間の数）を表示し、保護者が2回押して確定する。7ストアを1つの書き込みトランザクションで全消去してから書き込む。書き込みの登録中に例外が出たらトランザクションを中止し、後から失敗した場合もトランザクションごと取り消されるので、元のデータは1件も変わらない。成功したらアプリを読み直す。
- **復元前の備え**：今のデータの自動保存はしない（利用者の選択）。復元欄に「先に今のデータを保存して」と表示し、同じ画面の保存ボタンへ誘導する。
- **初期化**：消える内容を文で示し、2回押しで確定する。復元と同じ仕組みで7ストアを空にし、読み直す。学年やペットは初期値に戻る。
- **確認の操作**：`confirm()` は使わず、UIデザイン基準どおり1回目で危険色と「もう一度押す」文言に変え、3秒で元に戻す。
- **保護者確認**：計算問題や長押しなどの保護者確認は付けない（2026-11-26、利用者の判断）。子どもが誤って初期化・復元する可能性は、2回押しの確認と保存ファイルからの復元で受け入れる。

## Consequences

- 書き出したファイルは同じ内容で戻せる（自動テストで古い形式の記録を含めて確認）。ブラウザでも保存→初期化→復元→再保存で全ストアが一致した。
- 検査は構造だけなので、保護者がファイルを手で書き換えた場合の意味の正しさまでは保証しない。
- 復元・初期化の後に、別のタブで開いたままの古い画面が書き込むと、復元後のデータに古い状態が混ざりうる。単一端末・単一利用者の前提では対策しない。
- 端末間の復元（iPhoneで保存してタブレットで戻すなど）とiOSでのファイル保存は、実機で確かめる。
