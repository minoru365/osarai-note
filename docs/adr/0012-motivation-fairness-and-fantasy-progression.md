# ADR-0012: モチベーションの公平な加算とファンタジー装備進化

- Status: Accepted
- Date: 2026-09-06
- Supersedes: ADR-0006 のポイント加算規則と初期ペット種類の記述

## Context

ADR-0006の実装は回答イベントごとにポイントを加算していたため、1問を誤答してから正解すると2ポイントになっていた。また、2種類を育て終えた後の表示は止まり、成長しても絵の変化が小さかった。子どもが「何問できたか」と報酬を結び付けて理解でき、学習の再挑戦を損なわない設計へ整理する必要がある。

## Decision

- ポイントは、表示された問題が正解として完了した時に1問1ポイントだけ加算する。誤答、途中の「分からない」、正解までの再試行は追加ポイントにならない。既存残高は再計算・減額しない。
- ペットは固定順の3種類とする。`hiyoko` は勇者、`usagi` はプリンセス、`kitsune` は魔法使い。役割名は種類IDから表示時に導出し、保存データへ重複保存しない。将来の追加は配列、プロフィール、素材マニフェストへ末尾追加する。
- 各ペットは100ポイントごとに5段階の装備へ進む。400〜499ポイントは第5段階の成長中、500ポイントで仲間になり、次の種類へ決定的に切り替える。上限を超えるエサは拒否してポイントを消費しない。
- 72時間以上回答がない時の待機表情は表示だけの派生状態とし、残高、装備、成長、完了履歴を後退させない。回答日時は遅れて保存された古い時刻で巻き戻さない。
- 子ども向けの追加導線として、今日の完了問題数から3・5・10問の小さな目標と、直近7日の学習日スターを導出する。連続日数、ランキング、ガチャ、失敗による減点は持たない。
- 画像は3種類×5段階×通常/待機×2フレームの60枚を用意し、Service Workerでオフラインキャッシュする。画像の読み込み失敗時は種類ごとの絵文字へ戻す。現在の配信素材は256×256の透過PNGで、表示時に108pxへ収める。

## Consequences

- 旧データでひよこと「うさぎ」を完了してactiveが空の状態は、読み出し時だけきつねの育成中へ正規化する。残高、完了日時、最終回答日時は変えない。
- ポイント付与は漢字・単位・自由練習の保存トランザクション内で、問題完了時だけ行う。重複回答とトランザクション失敗では二重計上しない。
- 3種類目の完了後は育成対象がなくなり、残高は保持したまま完了表示になる。将来4種類目を追加する際は後方互換方針を再確認する。
- JSONバックアップ・復元が実装された時は、モチベーション状態と3種類の順序検証を対象に含める。
