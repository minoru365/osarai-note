# ADR-0013: スマートフォン縦向きにも対応し、読みやすさをUIデザイン基準へ寄せる

- Status: Accepted
- Date: 2026-11-26
- Supersedes: [study-support-plan.md](../study-support-plan.md) 1章の「スマートフォン対応や一般的なレスポンシブ設計は行わず、横向きタブレットへ固定する」

## Context

初期版はXiaomi Pad 6の横向き（基準表示1,440×900 CSS px相当）だけを対象とし、`body` に `min-width: 1000px`、PWAに `orientation: "landscape"` を指定していた。2026-11-26に、スマートフォンでも全画面を使いたいという要望と、共通のUIデザイン基準（`.ai/UIデザイン基準.md`）へ寄せたいという要望を受けた。

基準の配色は青系だが、このアプリは子ども向けの緑系で作り込んでおり、ペット素材とも合わせている。利用者は「寸法と読みやすさだけ合わせ、配色は残す」を選んだ。

## Decision

- 全画面をスマートフォン縦向き（375px幅を検証基準、320pxでも崩れない）で使えるようにする。
- **タブレットの配置は変えない。** 既存の2列レイアウトを基本とし、幅999px以下でだけ1列の配置へ切り替える。切り替え幅は基準の768/1200pxではなく999pxとする。学習画面の2列は約1,040pxを要し、1200pxにするとタブレットが新しい配置へ移ってしまうため。
- 書き取りの手書き欄は、タブレットでは従来どおり枠474px・入力470pxを保つ。スマートフォンでは書き取り画面を `100svh` の1画面に固定してページを動かさず、手書き欄は残った高さと幅に収まる大きさ（140〜470px）にする。ページが動くと書いている指でページがずれるため（2026-11-26にiPhoneで確認）。欄の大きさは書き取りカードを唯一の基準（size container）として決め、書いている間に上の部品の高さが変わらないよう状態表示の高さを固定する。高さの短い画面（760px以下）では問題文を詰め、見出し行を省く。横向きのスマートフォンでは問題と手書き欄を横に並べる。JSに渡す大きさとCSSの大きさは同じ測定値から決め、回転などで大きさが変わったときは手書き欄を作り直す（その字の書きかけは消える）。
- 日本地図も手書き欄と同じくスクロールを受け付けないため、スマートフォンでは高さを抑える。
- 読みの50音表は、スマートフォンでは1行を「あいうえお」の5列にし、あ行を上にした10行で並べる。DOMの順は変えず、CSSで配置だけ変える。
- UIデザイン基準からは寸法と読みやすさを採る：操作の高さ44px以上、補助文字14px以上、入力欄16px以上、文字と背景のコントラスト4.5:1以上、押せない状態を透明度ではなく専用の色で示す。配色（緑系）・フォント・角丸の雰囲気は変えない。
- PWAの `orientation` を `any` にする。インストール済みのタブレットでも横向き固定が外れる。端末側の回転ロックで固定する。
- Service Workerのキャッシュ名を上げ、インストール済みの端末が古いmanifestを使い続けないようにする。

## 不変条件

| 項目 | 守ること | 確認方法 |
|---|---|---|
| タブレットの配置 | 1,440×900と1,280×800で、読みやすさの調整以外の配置が変わらない | 変更前後のスクリーンショット比較 |
| 手書き欄 | タブレットで枠474px・入力470px・SVG470px | 実ブラウザの計測 |
| スマートフォンの書き取り | どの画面でもページがスクロールせず、ボタンまで1画面に収まる。手書き欄は375×812で314px、393×659で246px、320×640で209px。「分からない」などで状態表示が変わっても欄は作り直されない | 実ブラウザの計測 |
| 保存データ | IndexedDB名・スキーマ・問題ID・回答履歴の形式を変えない | 変更しない（自動テスト） |

## Consequences

- 画面ごとにスマートフォン用の上書きが増える。新しい画面を作るときは999px以下の表示も確かめる。
- 書き取りの判定は手書き欄の大きさに比例するため、小さな欄では指の誤差の影響が相対的に大きくなる。実機で書きやすさを確かめる。
- 文字の最小サイズを上げるため、タブレットの密な一覧（漢字の履修設定など）で1行に収まる数が変わることがある。
