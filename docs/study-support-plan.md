# おさらいノート 開発計画

最終更新：2026-08-14

この文書は、今後実装する仕様と開発順序の正本とする。実装済みの内容と直近の作業状況は [progress.md](./progress.md)、重要な技術・設計判断の理由は [adr/](./adr/) に記録する。

## 1. 目的と対象

小学4年生が家庭で1日10分程度、苦手な内容を優先して復習できるアプリを作る。主な利用者は児童、設定と問題管理の補助利用者は保護者とする。

- 優先順位：漢字、単位、分数、日本地図、理科
- 漢字の対象：小学3年生・4年生の配当漢字
- 基準端末：Xiaomi Pad 6、横向き16:10
- 基準表示：1,440×900 CSS px相当
- 提供形態：Android版Chromeから利用するPWA
- 初期版：単一端末・単一利用者、アカウントとクラウド同期なし
- 保存先：端末内IndexedDB
- 保存しない情報：氏名、学校名、生年月日、位置情報、生の筆跡、筆圧、端末固有情報

## 2. 学習体験の原則

- 児童向け画面には、保存方式や技術検証など開発者向け情報を表示しない。
- 問題文、操作、フィードバックは短くし、不正解を責める表現を使わない。
- 読みと書きは別能力として記録し、上部中央のタブで自由に切り替える。
- 読み終了後に書きへ自動移動しない。
- すべての学習画面に、明示的なホーム導線を表示する。
- 未習設定された漢字を含む問題は自動出題しない。
- 確定済み回答は即時保存し、未確定の読み入力や途中の筆跡は保存しない。
- スマートフォン対応や一般的なレスポンシブ設計は行わず、横向きタブレットへ固定する。

## 3. 漢字学習

### 3.1 読み問題

- 文中では対象語句のうち漢字部分だけを強調し、その漢字部分の読みだけを答える。送り仮名は表示するが回答に含めない（例：`悪い` → 強調は `悪`、回答は `わる`）。
- 回答は、右側のひらがな50音表をタップして入力する。
- カタカナ切替、長音「ー」、小さい「ゎ」は設けない。
- 濁点・半濁点は大きな記号で表示し、直前の文字へ適用する。
- 小文字は「ぁぃぅぇぉゃゅょっ」を直前の文字へ適用する。
- 50音表は右端をあ行とし、左方向へ、か・さ・た・な・は・ま・や・ら・わ行を並べる。
- 誤答後は同じ問題へ再回答でき、正解後だけ「次へ」を表示する。
- 「分からない」は1ミスとして記録して正しい読みを表示する。確認後は答えを隠し、自分で正解を入力するまで「次へ」を表示しない。
- 最終問題後は完了を表示し、書きへの移動は上部タブだけで行う。

読みは回答対象の漢字部分をひとまとまりとして評価する。誤答または初回正解の結果を、問題の `targetKanji` に含まれる全漢字の reading 集計へ1回ずつ反映する。同じ漢字が語句内に複数回あっても重複加算しない。

### 3.2 書き問題

- 問題文はかなと文脈を提示し、回答前に正解漢字を表示しない。
- 複数字の語句は、語句全体を1問として一字ずつ書かせる。
- Hanzi Writerと日本語ストロークデータで、画数、書き順、方向、位置を一画ごとに判定する。
- 正しく書き終えるまで「次へ」を表示しない。
- 「分からない」は1ミスとして記録し、答えと書き順見本を表示する。
- 見本確認後も、正しく書き直してから次へ進む。
- Xiaomi Pad 6では、手書きガイド、入力領域、Hanzi Writer SVGを固定470×470pxで一致させ、画面サイズに応じて拡大縮小しない。
- 結果は文字ごとに記録し、間違えた文字だけの writing 苦手度を更新する。
- 生の筆跡と筆圧は保存しない。

書き順データは全402字について、日本の学校で教える字形・書き順との一致を人が確認する。正しい児童の入力を過度に拒否しないよう、Xiaomi Pad 6で判定許容度を実測する。

### 3.3 履修設定

- 3年生200字、4年生202字を学年別に一覧表示する。
- 各漢字を「習った／まだ習っていない」へ切り替えられる。
- 3年生は初期状態を習った、4年生は保護者が学校進度に合わせて設定する。
- 設定変更は以後の出題だけに反映し、過去履歴を削除しない。
- 進行中セットの候補は変更せず、次に作るセットから反映する。

### 3.4 カスタム問題

保護者が読み・書き問題を登録、編集、有効化、無効化、削除できるようにする。標準問題と同じ共通素材形式を使い、可能な限り読みと書きをペアで作る。

- 削除は確認後の論理削除とし、過去履歴を維持する。
- 未習漢字を含むカスタム問題も自動出題しない。
- 標準問題にない漢字は、書き順データの存在を登録時に検証する。

## 4. 毎日の学習

### 4.1 セッション単位

- 読み・書きとも、開始操作ごとに最大10問の新しいセットを作る。
- 問題順は回答中だけ固定し、ホームへ戻る、アプリを閉じる、読み／書きを切り替える操作では未完了位置を再開しない。
- ホームには当日確定した「読み x問」「書き x問」の累計を表示する。
- 10問未満しか候補がなければ存在する分だけ出題し、候補が0問なら設定確認を案内する。
- 完了画面には、初回正解、ミスあり正解、「分からない」の件数と、「ホーム」「もう10問」を表示する。

### 4.2 出題順位

初期モードは練習回数の少ない順とする。開始時に次の順で候補を並べる。

1. 対象漢字の練習回数が少ない
2. 同じ練習回数なら、開始ごとに変わる乱数で並べる

- 練習回数は `targetKanji` 全字の対象モード `presentations` の最小値を使う。
- まだ練習回数が少ない漢字を含む熟語を先に扱う。
- 同一セット内では、対象漢字が重ならない問題を優先する。10問揃わない場合だけ重複を許す。
- 開始後に苦手度が変わっても、進行中セットの順番は変更しない。

### 4.3 追加学習と再抽出

- 完了後の「もう10問」とホームの「今日の漢字」は、その時点の練習回数から新しく抽出する。
- 当日出題済みかどうかは候補順位に使わず、同じ問題の再利用を許す。
- 当日中にホームへ戻る、またはアプリを閉じた場合も、次回は新しく抽出する。
- 未確定の読み入力と途中の書き入力は破棄し、その問題を最初から表示する。
- セッション日は開始時の端末ローカル日付で固定する。日付変更後に再起動または再表示した場合は新しい当日セットを作る。
- 前日の確定回答は保持し、未完了セットだけを再開対象外とする。

## 5. 漢字単位の記録と苦手度

集計キーは「漢字 × reading/writing」とする。問題IDは出題履歴を追跡するために残すが、苦手度の主キーにはしない。

各漢字・形式について次を保持する。

- 出題回数
- 初回正解回数
- 1回以上ミスした出題回数
- 「分からない」使用回数
- 書きの累計誤画数
- 苦手度（0〜10）
- 最終出題日時
- 最終初回正解日時

苦手度の更新規則は次のとおりとする。

- 最初の誤答または「分からない」で、その問題遭遇について1回だけ+1する。
- 同じ問題内で何度間違えても、苦手度の加算は1回までとする。
- 誤答後に正解しても、その問題内では加算を相殺しない。
- 誤答・見本なしで最初から完了した場合だけ-1する。
- 下限0、上限10とする。
- 累計ミスは過去の事実として減らさず、苦手度だけを増減する。

回答履歴を正本とし、漢字別集計は履歴から再計算可能な派生データとする。履歴追加、セッション更新、苦手度更新は同一トランザクションで確定し、同じ回答ID・セッション項目IDの再試行で二重計上しない。

## 6. 問題データと生成

### 6.1 生成対象

3年生200字、4年生202字について、各漢字の常用漢字表上の音読み・訓読みを1項目ずつ問題化する。

生成キー：`学年 × primaryKanji × readingType × canonicalReading`

音読み2つ、訓読み1つを持つ漢字なら共通素材を3件作り、各素材から読み問題1問と書き問題1問を生成する。人名専用読みは対象外とし、送り仮名が異なる訓読みは別項目とする。

### 6.2 共通素材

読み・書きを別々に手入力せず、次の共通素材からペア生成する。

- `pairId`：読みと書きを結ぶ不変ID
- `grade`：3または4
- `primaryKanji`：今回の読みを網羅する主対象漢字
- `readingType`：音または訓
- `canonicalReading`：基準読み
- `word`：出題語句
- `wordReading`：語句全体のひらがな読み
- `promptBefore` / `promptAfter`：読み問題の例文
- `targetKanji`：語句に含まれる評価対象漢字
- `writingPrompt`：答えを露出しない書き問題文
- `sourceRef`：読みと語例の根拠・版
- `reviewStatus`：未確認、確認済み、要修正

音読み一覧のカタカナ表記は `canonicalReading` に保持できるが、児童の回答 `wordReading` はひらがなへ統一する。連濁、促音化、活用などで表面読みが変わる場合も、基準読みと語句全体の読みを分けて保持する。

### 6.3 学年相当の表記

- 3年生問題では1〜3年生、4年生問題では1〜4年生の配当漢字だけを例文に表示する。
- 読みと書きで共用する `word` 内の漢字も、その問題の学年までに限定する。上位学年漢字を含まない自然な語句が作れなければ、自動公開せず `要修正` とする。
- 今回答えさせる `primaryKanji` と `targetKanji` はひらがな化しない。
- それより上の学年で習う漢字は、文中での実際の読み方に合わせてひらがなへ変換する。
- 文字単位の置換ではなく、熟語、連濁、音便、活用、送り仮名を考慮する。
- 自動変換に確信がない問題は `要修正` とし、公開しない。

### 6.4 生成・レビュー工程

1. 版付きの学年別漢字・音訓読み一覧を作る。
2. 各生成キーに対して語句、例文、書き問題文の候補を作る。
3. 上位学年漢字を文脈上の読みでひらがな化する。
4. 共通素材から読み・書きJSONを生成する。
5. 欠落、重複、ペア整合、学年配当、入力可能文字を機械検査する。
6. 読み、送り仮名、自然さ、学年相当性、日本語字形を人が全件確認する。
7. `確認済み` の素材だけをバージョン付き問題パックへ含める。

生成スクリプトは再実行可能にし、レビュー済みの修正を失わないよう、基準一覧、共通素材、生成物を分離する。生成AIを候補作成に利用しても自動公開しない。

## 7. その他の教科

漢字MVPの完成後、次の順で追加する。漢字以外の教科を追加する段階で、教科横断の「今日の復習」と出題比率を別途設計する。現時点では比率を固定しない。

### 単位

- 長さ、重さ、かさ、時間、面積
- 単位変換、大小比較、適切な単位、量感、文章題

### 分数

- 図、数直線、真分数・仮分数・帯分数、相互変換、大小比較、同分母の加減

### 日本地図

- 都道府県名と位置の双方向、地方区分、形、都道府県名の漢字連携

### 理科

- 4年生単元の図解、実験結果の予想、観察結果の読み取り、理由選択

## 8. 主要画面

### 児童向け

- ホーム：今日の読み・書き累計、毎回新規開始、教科入口
- 読み：問題文、回答欄、ひらがな50音表、正誤、次へ
- 書き：問題文、文字進捗、手書き欄、最初から、分からない、次へ
- 完了：初回正解、ミスあり正解、分からない、ホーム、もう10問
- がんばり記録：学習日数、できるようになった漢字、苦手漢字

### 保護者向け

- 漢字一覧と履修設定
- 漢字ごとの読み・書き集計と履歴
- カスタム問題管理
- 問題レビュー状況
- バックアップ、復元、初期化

保護者向け機能には簡単な保護者確認を設ける。認証ではなく誤操作防止を目的とし、端末自体の画面ロックを前提とする。

## 9. データ、バックアップ、安全性

IndexedDBの内部名 `study-support` は既存データ互換のため変更しない。次のデータを保存する。

- 回答履歴
- 回答中セッションと各問題の進行状態（次回開始時には再開しない）
- 漢字別の履修状態と読み・書き集計
- カスタム問題
- アプリ設定

JSONバックアップにはスキーマ版を含め、設定、履修状態、カスタム問題、セッション、回答履歴、漢字別集計を書き出す。復元は全データ検証後に単一トランザクションで置き換え、途中失敗時は既存データを維持する。削除・初期化・復元は、対象を明示して保護者が再確認した後だけ実行する。

DBスキーマ更新時は、既存履歴、未習設定、カスタム問題を保持する移行テストを先に作る。問題パック更新やPWA更新でIndexedDBを削除しない。

## 10. 技術・配信方針

- フロントエンド：React、TypeScript、Vite
- 手書き判定：Hanzi Writer＋日本語ストロークデータ
- 保存：IndexedDB
- 配信：GitHub Pages
- オフライン：Web App Manifest＋Service Worker
- 標準問題：`public/content/` のバージョン付きJSON
- CI：GitHub Actionsでテスト、ビルド、Pages成果物生成

初期公開は手動実行とし、mainへのpushによる自動公開は実機試用後に判断する。公開物にはアプリ本体と標準問題だけを含め、学習履歴、バックアップ、秘密情報を含めない。

Hanzi Writer、ストロークデータ、問題作成に利用する資料は、ライセンスと再配布条件を記録する。日本語字形と書き順は公式資料・KanjiVG等を照合し、人による確認を必須とする。

## 12. 検証と完了条件

### 自動テスト

- 問題データの欠落、重複、ペア整合、学年配当、ひらがな入力可能性
- 50音入力、濁音、半濁音、小文字、削除、読み判定
- 読みの連帯責任、書きの文字別集計、苦手度上下限
- 練習回数順、同数ランダム、対象漢字重複回避、候補不足
- 読み・書き各最大10問、タブ切替時の新規抽出、日付変更、もう10問
- 同一回答ID・セッション項目IDの冪等性
- 履歴と集計の同一トランザクション、失敗時の不変性、履歴からの再集計
- 未習除外と履歴維持
- DB移行、バックアップ、復元、壊れた形式の拒否
- GitHub Pages用ビルドとオフライン再起動

### 実機確認

- Xiaomi Pad 6の指・ペン入力の追従性
- 正しい字の誤拒否率と誤った書き順の拒否
- 50音表と操作ボタンのタップしやすさ
- 説明なしで開始、回答、再開始、完了できること
- 読み10問・書き10問が各10分程度を大幅に超えないこと
- 子どもにとって問題文、フィードバック、ごほうび表現が自然であること
